# 택이네 조개전골 — 식당 재고 관리 시스템

> 🇰🇷 **한국어** · 🇻🇳 [Tiếng Việt](README.vi.md)

한국 식당을 위한 원재료 재고·판매·발주 관리 앱입니다. React + TypeScript + Vite 로 만들었고,
서버 없이 브라우저 안에서 동작합니다.

> **언어 규칙:** 사용자 화면에 보이는 모든 문구는 100% 한국어입니다.
> 코드·변수·타입·DB enum 은 영어를 쓰고, 화면에 나가는 값은 전부 `src/lib/labels.ts` 를
> 거쳐 한국어로 바뀝니다.

## 기능

### 0. 메뉴·레시피 (`설정` → `메뉴 · 레시피` 탭)
메뉴 1인분에 어떤 원재료가 얼마나 들어가는지 등록합니다.

- 메뉴별 **원가 / 마진 / 원가율 자동 계산**, 기준 초과 시 색으로 경고
- 현재 재고로 **몇 인분 가능한지**, **어떤 재료가 먼저 떨어지는지** 표시
- `판매 등록` 화면: 판매 인분 입력 → 차감될 재료 미리보기(같은 재료는 합산) → 확정 시
  재고 차감 + 매출 기록. 재료를 한 줄씩 입력할 필요가 없습니다
- 재고가 모자라면 확정 전에 경고

> 판매가 실제 출고 거래를 만들기 때문에 **수요 예측이 저절로 정확해집니다** — 예측 엔진은
> 예전처럼 출고 이력을 읽을 뿐 코드를 바꾸지 않았습니다.

### 1. 재고 관리 (데이터 저장)
- `localStorage` 에 저장되어 새로고침해도 유지
- 원재료·공급업체 추가/수정/비활성화
- 입고 / 출고 / 재고 조정, 모든 동작이 거래로 기록
- 재고 상태 규칙: `정상` / `재고 부족` / `품절`
- 유통기한 상태 별도: `유통기한 임박` / `오늘 만료` / `유통기한 경과`
- CSV 내보내기 (UTF-8 BOM 포함 — 엑셀에서 한글이 깨지지 않음)
- JSON 백업 / 복원

### 2. 수요 예측 (`수요 예측`)
- **선형 가중 이동평균**(최근일 우선)으로 하루 사용량 계산
- **폐기·손실은 수요에서 제외**하고 폐기율 지표로 따로 표시
- 소진 예상일, 최근 7일 vs 이전 7일 추세, 예측 신뢰도, 유통기한 내 소진 불가 예상 금액,
  재고 회전율

### 3. 발주 관리 (`발주 관리`)
`재주문점 기준` / `요일 기준` 두 가지 예측 방식을 버튼으로 전환합니다.

**재주문점 기준** — 건조식품·양념처럼 매일 고르게 쓰는 품목용
- 재주문점 = (하루 사용량 × (리드타임 + 안전 일수)) + 최소 재고

**요일 기준** — 신선 수산물용
- 입고 날짜 선택 → **같은 요일 최근 4주**(휴무일 제외)의 원재료별 사용량 평균
- 오늘부터 그 날 전날까지 각 날짜의 예상 사용량(그 요일 방식으로)을 빼서 당일 아침 예상 재고 산출
- 권장량 = 요일 평균 − 예상 재고, 단위에 맞춰 올림
- 표본 4개를 그대로 보여 주어 편차를 확인할 수 있음. 표본 주 수 변경 가능(3/4/6/8)

이 방식이 필요한 이유: 식당은 요일별 편차가 큽니다. 데모 데이터에서 바지락은 토요일 35kg,
월~수는 18kg 입니다. 이동평균은 평일에 과다, 주말에 부족 발주로 이어집니다.

- 발주 필요 품목을 **공급업체별로 묶어** 제안
- 발주서 흐름: `작성 중` → `발주 완료` → `입고 완료`, "입고 처리" 시 재고 자동 반영
- `발주서 만들기` → 표 형식 문서 미리보기 → `인쇄 / PDF 저장` / `파일 저장` / `엑셀(CSV)`
- 단가·금액 칸은 비워 둠(공급업체 기입)
- `문자 보내기`: 카카오톡에 붙여넣을 한국어 발주 문자 생성. 클립보드 복사는 두 단계
  대체 방식이 있어 `http://192.168.x.x` 같은 비보안 컨텍스트에서도 동작

### 4. 영수증 스캔 (`입출고 관리` → `영수증 스캔` 탭) — 핵심 기능
영수증 사진 → 품목 표 추출 → 검토 → 버튼 하나로 입고.

- 휴대폰 카메라 촬영 또는 사진 선택
- 전송 전 **긴 변 1600px 로 축소**해 용량·비용 절감
- **영수증 품목명을 등록된 원재료와 자동 매칭**(바이그램 유사도). 매칭 실패 줄은 체크 해제 + 경고
- 검토 표에서 수량·단가 바로 수정
- 확정 → 입고 거래 일괄 생성, 단가·유통기한 갱신
- **단가 급등 경고**: 최근 60일 입고 평균과 비교, ±10% 알림(노랑), ±20% 경고(빨강), 저렴하면 초록.
  차단하지 않고 알려만 줌. 수동 입고 화면의 단가 칸에도 동일 경고

#### 인식 방식 3가지 (`설정` 에서 변경)

| 방식 | 설명 |
|---|---|
| `claude` | 공식 SDK 로 Claude 비전 호출. 한국어 영수증 정확도 최고. 본인 API 키 필요 |
| `tesseract` | 기기 안에서 실행, 무료, 오프라인. 감열 영수증 정확도는 낮음 |
| `demo` | 실제 사진을 읽지 않고 예시 명세서 반환. 설정 없이 전체 흐름 체험용 |

기본값은 `demo`. 실제로 쓰려면 `설정` → `Claude 이미지 인식` → API 키 입력.

**보안 주의:** 브라우저에서 직접 API 를 호출(`dangerouslyAllowBrowser`)하므로 키가 그 기기의
`localStorage` 에 저장됩니다. 개인 기기에서만 쓰세요. 직원 여러 명이 쓰게 하려면 키를 감출
작은 중계 서버가 필요합니다.

### 5. 일일 마감 (`일일 마감`)
- 실사 수량 vs **장부 재고**(판매 레시피 차감 반영) 비교
- 차이를 수량·금액으로 즉시 표시(빨강 = 부족, 파랑 = 초과)
- 차이 있는 품목만 입력, 비워 두면 차이 없음으로 건너뜀
- 확정 → `재고 조정`(사유 `실사 차이`) 거래 생성, 재고를 실사값으로 맞춤
- **`반복해서 손실이 나는 원재료`**: 마감 이력 누적으로 계속 비는 품목 표시
  (예: "바지락 · 마감 3회에서 부족 · 누적 3.1kg · -₩27,900")

### 6. 대시보드
- **매출 구성 누적 막대**: 높이 = 매출, 아래 = 원가, 위 = 마진. 단위가 같으니 축은 하나만 —
  이중 축은 쓰지 않습니다. 호버 시 매출/원가/마진/원가율. 직접 표기는 최고점에만
- **원가율 게이지**: 큰 숫자 + 목표 구간 30~38%, 색만이 아니라 `적정 / 주의 / 높음` 글자로도 표시
- **요일별 매출 히트맵**: 8주 × 7일
- **분류별 원가 비중**: 단일 색상 명도 단계(색은 순위를 뜻함), 하위는 "그 외"로 묶음
- 분석 기간 7 / 14 / 30일 전환

색 조합은 눈대중이 아니라 **검증 스크립트로 확인**했습니다: 원가/마진 쌍은 흰 배경에서
CVD ΔE 24.7, 일반 시야 ΔE 33.6; 비중 막대 4단계는 단일 색상·명도 단조·최저 대비 2.11:1.


## 기술 메모

- Anthropic SDK 의 `zodOutputFormat` 은 **zod v4** 스키마를 요구하므로 `claudeProvider.ts` 는
  `zod/v4` 에서 import 합니다(zod 3.25 가 제공하는 하위 경로).
- 재고를 바꾸는 모든 동작은 **반드시 `moveStock` 을 거칩니다**. `moveStock` 직후 예전 상태의
  객체로 `upsertIngredient` 를 호출하면 방금 더한 재고가 덮어써집니다. 입고 시 단가·공급업체·
  유통기한 갱신은 이미 리듀서 안에서 처리됩니다.
- 판매 등록과 마감 확정은 재고 반영과 기록 저장을 **하나의 액션**으로 처리합니다. 두 단계로
  나누면 한쪽만 반영된 어중간한 상태가 생깁니다.
- 저장 키는 `taekine-inventory-v3`. 이력은 **판매 → 레시피 → 재료 차감** 순서로 생성되어
  매출·원가·사용량이 서로 맞습니다. v3 는 실제 매장 메뉴판(38 메뉴, 35 원재료, 8 공급업체)
  기준이라 v1/v2 데이터는 이어 쓰지 않습니다.
- 메뉴별 재료 소요량은 원가율 22~47% 가 나오도록 잡은 **추정치**입니다. `설정 → 메뉴·레시피`
  에서 실제 레시피로 고치세요. 메뉴판을 그대로 옮기지 못한 두 곳: `스페셜 조개전골`("토핑 1가지
  택")은 낙지 기준, `살아있는 여수돌문어`("무게에 따라 가격 변동")는 메뉴 표기 가격 기준입니다.
- 원재료 단가는 이제 장식이 아니라 **실제 숫자**입니다 — 메뉴 원가가 여기서 계산됩니다.
- 차트에서 요일 라벨을 React `key` 로 쓰면 안 됩니다(14/30일 기간에서 중복). 날짜를 `id` 로 씁니다.
- 반영된 영수증 이미지는 `localStorage` 용량 때문에 저장 시 제거됩니다.
- 데모 영수증 단가는 시드 매입가에 맞춰 두었고 바지락만 약 24% 높게 잡아 급등 경고를
  보여 줍니다.

## 안드로이드 설치

**[ANDROID.md](ANDROID.md)** 에 두 가지 방법이 있습니다(호스팅 후 PWA 설치, 또는 Capacitor 로
APK 빌드). 안드로이드 프로젝트는 `android/` 에 준비되어 있습니다.

```bash
npm run build          # 웹 빌드 + 서비스 워커·매니페스트 생성
npm run android:sync   # 빌드 후 안드로이드 프로젝트로 복사
npm run android:open   # Android Studio 로 열어 APK 빌드
npm run icons          # 앱 아이콘 다시 그리기
npm run android:icons  # 안드로이드 런처 아이콘 다시 그리기
npm run screenshots    # README 화면 캡처 (개발 서버 실행 중이어야 함)
```

## 매장 내 네트워크 공유

Vite 는 `host: true` 로 모든 네트워크 인터페이스에서 대기합니다. 다른 기기는 `localhost` 가
아니라 **LAN IP** 로 접속하세요: `http://<서버-IP>:5178`. 윈도우에서는 관리자 PowerShell 로
포트를 한 번 열어야 합니다:

```powershell
New-NetFirewallRule -DisplayName "Taekine Dev Server" -Direction Inbound -Protocol TCP -LocalPort 5178 -Action Allow -Profile Any
```

그래도 안 되면 공유기의 AP/Client Isolation 설정을 확인하세요.

**주의:** 데이터는 기기마다 따로 저장됩니다(`localStorage`). 사장님 휴대폰과 직원 휴대폰은
서로 다른 재고를 보게 됩니다. 여러 명이 같은 숫자를 봐야 한다면 서버와 DB 가 필요합니다 —
별도 작업입니다. 그전까지는 `설정 → 데이터 관리 → 백업 파일 내려받기` 를 주기적으로 하세요.
